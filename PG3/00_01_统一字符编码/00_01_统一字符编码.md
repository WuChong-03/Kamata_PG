# 统一字符编码

计算机需要通过一定的规则，把二进制数据解释成文字。这个规则就叫 **字符编码（文字コード）**。如果保存、编译、显示时使用的编码不一致，就可能出现乱码。

---

## 1. 常见字符编码

### 1.1 ASCII

ASCII 是早期常用的字符编码，只能表示约 `128` 个字符，主要用于英文、数字和符号，无法表示中文、日文等多语言文字。

### 1.2 Shift_JIS

Shift_JIS 是日本旧 Windows 环境中常见的字符编码，可以表示日文，也兼容 ASCII 的英文部分。但它在非日本系统或不同开发环境中容易出现兼容问题，因此现在逐渐被 UTF-8 取代。

### 1.3 UTF-8

UTF-8 是目前最常用的字符编码，支持几乎所有语言，并且与 ASCII 兼容。现在的 Web 开发、操作系统和大多数编程环境都广泛使用 UTF-8。

---

## 2. 统一 UTF-8 编码

字符编码问题通常分为三个部分：**文件编码、编译器解析、控制台输出**。这三个地方都需要统一，否则仍然可能出现乱码。

---

### 2.1 编译器设置

为了让编译器按 UTF-8 读取源码，可以]在`项目` → `属性` → `C/C++` → `命令行` 添加：

```cpp
/source-charset:utf-8
```
> 注意：这个设置不会修改文件本身的编码，只影响编译器读取源码的方式。

---

### 2.2 控制台编码设置

即使文件编码和编译器解析都正确，Windows 控制台仍然可能使用 Shift_JIS、GBK 或其他本地代码页显示文字，所以程序运行时还是可能乱码。

可以在`main()`加入：

```cpp
SetConsoleOutputCP(65001);
```

`65001` 表示 UTF-8 的代码页，也就是让控制台按 UTF-8 显示输出内容。

> 注意：这个设置只影响程序运行时的控制台显示，不影响文件编码，也不影响编译器解析。

---

### 2.3 文件编码设置

在 Visual Studio 中可以通过以下方式修改文件编码：

`文件` → `另存为` → `使用编码保存`

常见 UTF-8 选项有两种：

- `UTF-8 without BOM` : UTF-8 无签名，现代开发中更常用, 一般推荐使用

- `UTF-8 with BOM` : UTF-8 带签名，文件开头有特殊标记
    >BOM的作用是告诉某些软件：**这个文件是 UTF-8**。UTF-8 BOM 的字节是：`EF BB BF`例如 Excel 或旧 Windows 软件有时需要 BOM 才能正确识别 UTF-8。

KamataEngine 和 Novice 项目默认也通常使用`UTF-8 without BOM`

## 3. 多人开发中的编码统一

因此多人开发中通常会使用 `.editorconfig` 统一项目规则。通常会在保存文件时生效，因此建议在项目初期就设置好，避免后期多人文件编码混乱。

`右键解决方案` → `添加` → `新建项` → `文本文件` → 命名为 `.editorconfig`

```ini
[*.{cpp,h}]
charset = utf-8
``` 

---

## 4. Unicode 与 UTF-8 的区别

- Unicode 是`字符标准`，负责给每个字符分配唯一编号。

- UTF-8 保存这些编号的`编码方式`

| 字符 | Unicode 编号 | UTF-8 字节 |
|---|---|---|
| `あ` | `U+3042` | `E3 81 82` |

除了 UTF-8 以外，还有 UTF-16、UTF-32 等编码方式，但现代开发中最常用的是 UTF-8。
